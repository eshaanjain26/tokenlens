About TokenLens

What is TokenLens?

TokenLens is a client-facing LLM intelligence platform for comparing cost, performance and environmental impact across frontier language models. Data is sourced from peer-reviewed research and official provider sustainability reports.

Environmental Methodology

  • Power (Wh/1M tokens) — anchored to Luccioni et al. 2023 "Power Hungry Processing" (direct GPU measurement on A100s). 6B model ≈ 540–640 Wh/1M. Larger models scale as params^0.65.
  • CO₂ (g/1M tokens) — Power × provider grid carbon intensity (gCO₂/kWh). Source: Google Env Report 2023, Microsoft Sustainability 2023, AWS 2023.
  • Water (L/1M tokens) — Power × provider WUE (L/kWh). Calibrated to Li et al. 2023: ~500mL per 20-question GPT-3.5 session.
  • Reasoning models — 4–20× compute multiplier for extended chain-of-thought (o1/o3/DeepSeek R1).

Pricing Data

Live pricing fetched from OpenRouter API (public, no key required). Falls back to 30 curated hardcoded models if the API is unavailable. Prices may change without notice.

Important Disclaimer

All environmental figures are research-derived estimates. Actual energy, water and CO₂ values depend on real-time data center load, cooling method, and renewable energy mix. This platform is intended for directional decision-making, not regulatory compliance or audit reporting.

How every number is calculated

TokenLens derives each cost, CO₂, water and power figure from published research and live pricing. This page shows the formula pipeline, the assumptions behind it and the sources, so you can check any metric yourself.

Overview

Every figure follows the same five steps, in this order. Each step feeds the next.

  1. Tokens countedBPE approximation of the prompt and the reply
  2. Cost computedTokens times live OpenRouter pricing
  3. Power derivedTokens times a Wh-per-token rate anchored to Luccioni et al. 2023
  4. CO₂ computedPower times the provider grid intensity
  5. Water computedPower times the provider water usage effectiveness

Token counting

Tokens are the unit of LLM billing. TokenLens uses a byte-pair-encoding approximation calibrated to OpenAI's cl100k_base tokenizer. English text averages about 0.75 words per token (4 characters). Code is denser at about 3 characters per token. Multilingual text varies.

// Token count approximation (BPE-calibrated)
inputTokens  = ceil(charCount / 3.8)          // ≈ cl100k_base average
outputTokens = ceil(inputTokens × 1.8)         // typical generation ratio

// Context window accumulation (quadratic growth)
contextTokens_turn_k = P + (k-1) × (P + O)   // P=prompt tokens, O=output tokens

Sources OpenAI Tokenizer HuggingFace Tokenizers

Cost

Pricing comes from the public OpenRouter API (no key needed) in USD per million tokens. Input and output tokens are billed separately.

// Per-turn cost
cost = (inputTokens  / 1,000,000) × pricePerMInput
     + (outputTokens / 1,000,000) × pricePerMOutput

// Context accumulation multiplier (turns 2+)
contextBilling_k = inputTokens_k + (k-1) × (prevPrompt + prevOutput)

Sources OpenRouter API OpenAI pricing Anthropic pricing

Power

Power rates (Wh per million tokens) are anchored to Luccioni et al. 2023, "Power Hungry Processing", which measured 88 NLP tasks across 10 model families on identical hardware. A 6B-parameter model draws about 540 Wh per million tokens. Other rates scale with parameter count, sub-linearly because of quantisation and hardware gains.

// Anchor: 6B model ≈ 540 Wh/1M tokens (Luccioni 2023, Table 3)
// Per-model rates are research-calibrated; see POWER_RATES in source

power_Wh = (inputTokens + outputTokens) / 1,000,000 × powerRate_Wh_per_M

CO₂ emissions

Carbon intensity (gCO₂ per kWh) depends on where the provider runs its data centers. Values come from provider sustainability reports and EPA/EEA grid factors. A Google model on a renewable-heavy GCP grid therefore shows lower CO₂ than the same workload on a coal-heavy grid.

Water

Data center water use is reported as Water Usage Effectiveness (WUE): litres of water per kWh of IT load, covering cooling tower evaporation and mechanical cooling. Li et al. 2023, "Making AI Less Thirsty", estimated that training GPT-3 needed about 700,000 L of fresh water. TokenLens applies inference-scaled WUE from the same framework.

water_mL = power_Wh / 1000 × provider.wue_L_per_kWh × 1000

Methodology and sources

Four assumptions carry most of the weight in these numbers. Each is stated here so you can judge it.

Luccioni et al. 2023 power anchor

Every power rate hangs off one measured point: a 6B-parameter model draws about 540 to 640 Wh per million tokens on an A100 GPU. Larger models scale as parameters^0.65, which is sub-linear because inference is limited by memory bandwidth. Reasoning models add a further 4 to 20 times for extended chain-of-thought compute. Only the anchor is a direct measurement. Every other model rate is a scaled estimate from that point or from a provider report.

Cache-read energy factor

When prompt caching is on, a cache-read token is assumed to use 10% of the energy of a fresh input token. This factor is a TokenLens assumption, not a published figure. Cached tokens are still billed at the provider's discounted cache-read price, so the cost saving and the energy saving are calculated separately.

Token estimate

Prompts are converted to tokens at 3.8 characters per token, and replies are assumed to be 1.8 times the input length. Real tokenizers differ by model and language, so treat estimated token counts as approximate.

Provider profiles

Grid carbon intensity and water usage effectiveness are applied per provider, not per data center. A model hosted by a third party can run on a different grid than the profile assumes.

  1. Luccioni, A.S., Viguier, S., & Ligozat, A. (2023). "Power Hungry Processing: Watts Driving the Cost of AI Deployment?"arXiv:2311.16863
  2. Li, P., Yang, J., Islam, M.A., & Ren, S. (2023). "Making AI Less Thirsty: Uncovering and Addressing the Secret Water Footprint of AI Models."arXiv:2304.03271
  3. Patterson, D. et al. (2021). "Carbon Emissions and Large Neural Network Training."arXiv:2104.10350

Limitations

All environmental figures are research-derived estimates, not audited measurements. Real inference power depends on batch size, hardware utilisation, cooling efficiency and model quantisation, and providers do not publish any of these. TokenLens uses the best published values as conservative anchors.

Treat every CO₂, water and power figure as an order-of-magnitude benchmark.
